# fuzzy-dedup:跨导入批次的精确模糊去重库

对每条记录按指定字段构造词集合(NFKC → casefold → `str.isalnum()` 连续字符取词;
null/缺失/空串不产生词;同字段重复词只计一次;同一词在不同字段是不同元素),
以 Jaccard 相似度 ≥ 95%(`100*|A∩B| >= 95*|A∪B|`,含恰好等于)为匹配标准,
跨导入批次精确找出所有匹配记录对。只输出候选对,不做聚类或实体合并。

## API

```python
from fuzzy_dedup import DedupMatcher

matcher = DedupMatcher(["name", "desc"])   # 参与匹配的字段,创建后不可更改
matcher.import_batch("batch1", [{"id": "r1", "name": "...", "desc": "..."}, ...])
matcher.import_batch("batch2", [...])
pairs = matcher.find_pairs("batch1")       # [("r1", "r7"), ...]
```

- `import_batch(batch_id, rows)`:导入一批记录(每批 ≤ 5000 条,批次 ID 与记录 ID 全局唯一)。
- `find_pairs(batch_id)`:返回当前全部已导入记录中、至少一端属于该批次的所有匹配对
  (含批内匹配),每个无序对只出现一次。后续导入新批次后再次查询旧批次,
  仍会包含旧批次与新记录之间的匹配。

## 运行测试

```bash
python3 -m pytest tests/ -q -s
```

(`-s` 用于显示规模测试的实际耗时与内存数据;约 20 秒跑完全部 9 个测试。)

## 候选筛选为什么不会漏掉匹配对

设两条记录词集合大小为 `a`、`b`。匹配要求 `100·i >= 95·(a+b-i)`(`i` 为交集大小),
即 `i >= 19(a+b)/39`,因此对称差大小满足
`d = a + b - 2i <= (a+b)/39`,并且可匹配的尺寸必然满足 `19/20 <= a/b <= 20/19`。

索引端对每条大小为 `a` 的记录,在若干"层级"上各取两个独立的哈希分桶:
在层级 `L`,用哈希把每个词分进 `L` 个桶,对每个桶内全部词计算一个与顺序无关的
64 位签名(词哈希之和),把 `(层级, 分桶方案, 桶号, 记录大小, 桶签名)` 作为键,
将记录 ID 追加到对应倒排表。索引的层级集合为 `{d(a,b)+1 : b 为可匹配尺寸}`。

查询端对大小为 `b` 的记录,枚举所有可匹配尺寸 `a`,取层级 `L = d(a,b)+1`,
用同样的分桶函数计算自己的桶签名,取出两个分桶方案下对应倒排表的交集作为候选,
最后对每个候选用真实词集合精确验证阈值。

**不漏的证明**:若 `(A, B)` 匹配,则它们之间至多有 `d = d(a,b)` 个不共同的词。
在层级 `L = d+1` 上,每个"不共同的词"最多污染一个桶,`L` 个桶中至少有一个桶
完全由两条记录共同的词组成(鸽笼原理)。该桶在两条记录中的内容完全相同,
因此在两个独立分桶方案下都产生相同的桶签名,两条记录都会出现在该键的倒排表中,
查询必能把它们同时取到。签名碰撞只会多引入候选(随后被精确验证过滤),绝不会丢候选。

该方案只依赖"不匹配词数 ≤ d"这一由阈值直接推出的事实:不按字段、前缀或批次做
任何必要条件过滤,不截断候选、不删除高频词、不做近似召回;词频变化不影响正确性,
因为分桶函数是固定的(只依赖词本身,不依赖统计信息)。

## 测试覆盖

- `tests/test_correctness.py`:固定种子的随机数据,每次导入后与独立穷举参照实现
  逐批次比对;改变导入顺序与批次划分,最终匹配对集合一致;覆盖空集合、重复词、
  跨字段同词、Unicode 规范化(NFKC/casefold)与恰好 95% 的边界。
- `tests/test_frequency_shift.py`:后续批次大幅改变词频后,旧批次仍能查到新匹配,
  其中包含仅靠高频词重合就达到阈值的记录对。
- `tests/test_scale.py`:100000 条记录(每条 64 词,56 词全体共有;99000 条基础记录
  各含 8 个全局唯一词;1000 条变体各替换一个私有词),分 20 批导入并逐批查询,
  恰好得到 1000 个匹配对;断言总 CPU ≤ 60 秒、峰值 RSS ≤ 512 MiB,并打印实测值。
